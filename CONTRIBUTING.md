# Contributing to PlayBox

Thanks for taking the time to help improve PlayBox. Clear, reproducible feedback is more useful than a report that only says something is broken.

## Before opening an issue

- Search existing issues to avoid duplicates.
- Confirm which PlayBox version you are using.
- Check whether the problem is specific to one game or application.
- Remove passwords, tokens, personal paths, and other sensitive information from logs before sharing them.

## Bug reports

Please include:

1. PlayBox version.
2. Linux distribution and version.
3. Wine version and configuration details, when relevant.
4. The affected game or application.
5. Steps to reproduce the issue.
6. Expected result and actual result.
7. Relevant error output or logs.

A screenshot or short recording can help explain interface issues. Do not upload copyrighted game assets or private data unless you have permission to share them.

## Feature requests

Describe the problem first, then explain how your proposed feature would improve the workflow. Include examples where possible and keep requests focused on one idea.

## Pull requests

Before submitting a pull request, open an issue or discussion for substantial changes so the direction can be agreed upon. Keep changes focused and include a concise explanation of what changed and how it was tested.

## Be respectful

Keep discussions constructive and welcoming. Feedback about bugs, usability, performance, and compatibility is encouraged; personal attacks are not.
